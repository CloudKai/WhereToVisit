# Temporary browser social references

`/import` links to `/references`. This keeps a supplied social post URL and an optional original personal note. Saving and listing never retrieve sources or load provider resources. Optional Instagram display is described below; it never extracts Mentions, confirms Places, changes discovery rankings, or saves to Trips. The existing licensed Wikivoyage importer remains separate. Its source/evidence and account save rules are unchanged.

The server reuses the opaque, HttpOnly anonymous import-session cookie, never the account or guest credential. Switching accounts in the same browser still shows its browser-owned references. Another browser, even signed into the same account, has no reference authority. Signing in performs no transfer. The original link and note cannot be edited: delete a draft and save a new one deliberately if needed. A separate explicit branch choice is described below.

Each draft expires absolutely 24 hours after creation, capped by an earlier browser-session expiry. Reading does not extend either expiry. Twenty live drafts per browser are allowed. Optional notes use the shared policy: 500 Unicode code points after trimming, CRLF normalized to LF, ordinary line breaks allowed, other control/format characters rejected. Notes are rendered as text under “Your note.” Creator verification, publication/visit dates, current operation and popularity are unknown.

Only these exact HTTPS authority/path forms are structurally accepted:

- `www.xiaohongshu.com/explore/<24 lowercase hexadecimal characters>`
- `www.tiktok.com/@<2–24 ASCII letters/digits/dot/underscore>/video/<1–30 digits>`
- `www.instagram.com/p/<1–64 ASCII letters/digits/underscore/hyphen>/` and `/reel/<same>/`

One trailing slash is optional on input; Instagram stores one and the others omit it. Hosts are exact lowercase `www` forms. Credentials, explicit ports (including 443), alternate hosts, shortlinks, profile/search/story/photo paths, encoded paths, dot segments, backslashes, spaces and control/format characters are rejected. Query strings and fragments are discarded, never stored, and previewed as the exact canonical URL before saving. A stripped link may be unavailable; Xiaohongshu may require original sharing context. The app does not verify link existence or infer identity from path segments. External opening is an ordinary deliberate link with `noopener noreferrer` and `no-referrer`; no automatic platform request is implemented.

The [16 October access qualification](research/social-platform-access-qualification-2026-10-16.md) supports only this nonfetching reference boundary. The official TikTok embed example demonstrates its video URL shape, and Meta documents known post/reel display links. No official Xiaohongshu permalink specification was established: its narrow explore/24-hex shape is an application input syntax for supplied references, **not** an API contract or source availability/identity qualification. Unsupported shapes are rejected rather than resolved.

`0008_private_social_references` adds separate reference and create-attempt tables. Every list/read/delete excludes expired records and checks the live browser session. Unknown, expired and other-browser IDs all return the same 404. Same-origin writes, bounded 8192-byte JSON input, established five-second body deadline and `no-store` responses apply. Successful creates are limited to 40/minute/browser and 200/minute/IP; only HMAC IP digests are retained. At most 1,000 attempt rows and 20,000 reference rows are admitted globally. Failed input cannot allocate a reference. Creation/quota enforcement and deletion are transactional. No new dependency is required.

On each reference operation, at most 100 expired reference rows and 100 old attempt rows are physically removed. All expired rows are inaccessible even while that bounded cleanup catches up. Existing import-session cleanup can also cascade references when its parent session expires; this preserves the established session lifecycle rather than modifying licensed import cleanup. No scheduled cleanup job was added. During inactivity expired rows can remain physically present until a later operation; SQLite WAL/free pages, backups, secure erasure, scheduled operator cleanup, release abuse controls, HTTPS and deployment remain operating qualification gates. Deletion removes the live record and original note; it is not a promise of forensic erasure from storage history.

Run `npm run test:social-references` after a production build, with Docker Desktop and free 3100/8180 ports. This dedicated configuration generates its own secrets, fresh database and storage-test configuration; it never reuses a running server. It writes isolated test files under ignored `.data/`. The historical licensed import fixture is the bounded public source probe from 12 October, retained only in `tests/fixtures/`; it proves preservation of previously extracted evidence, not a fresh platform/source retrieval. Production modules never import this test fixture. Browser/public HTTP tests deliberately seed expiry in isolated storage; there is no production clock override. The broader account, guest, provider, scheduling and deployment suites are separate.

Optional Instagram previews are **off by default**. The qualified local pair uses an app origin such as `http://127.0.0.1:8380` and a separate wrapper `http://localhost:8381`, bound only to IPv6 loopback `::1`. Set `INSTAGRAM_PREVIEW_LOCAL_ENABLED=1`, `INSTAGRAM_PREVIEW_WRAPPER_ORIGIN=http://localhost:8381` and `BETTER_AUTH_URL` to the canonical 127.0.0.1 app origin in both processes, then run `npm run instagram:preview` beside the app. No hosts/DNS changes are required. App requests with another Host receive no preview configuration. Paths, credentials, public/HTTPS origins, alternate hosts and noncanonical origins are rejected or leave the feature disabled. Different ports alone do not isolate cookies. Do not use this qualification for an app hosted on localhost or arbitrary production domains. A browser with existing localhost cookies will receive the wrapper's unavailable response: the wrapper rejects all Cookie-bearing requests. Public deployment, other applications on localhost, browser policy and production cookie/CSP qualification remain separate work.

Only a deliberate **Load Instagram preview** creates a wrapper frame. Before loading, the user sees that Instagram receives the public permalink plus ordinary browser/network information and may use storage. It does not promise anonymity or credentialless provider requests. The wrapper receives no note, draft ID, actor, account, Trip data or app credential. It sets no cookies, performs no server source fetch, accepts only bounded canonical Instagram post/reel URLs, and renders a technical official blockquote plus official embed script. The script's observed redirect to `https://www.instagram.com/embed.js` is allowed explicitly; provider-generated frame URLs are never guessed. Provider code executes only on the separate wrapper/provider origins, never the app document or same-origin srcdoc. The wrapper policy limits its parent to the configured app origin. No resize/control messages are accepted. No provider HTML, caption, media, derived metadata, analytics or scores are persisted.

One preview is shown at a time. Hide, navigation, deletion, expiry and removal from a refreshed list unmount it. The fixed-height frame can scroll internally so attribution is not deliberately cropped. App status remains **requested; visibility unconfirmed** because cross-origin onload does not prove a visible post. The ordinary source link remains available for blank, disabled, private, removed, login-required and connectivity failures. Hiding cannot erase provider browser storage or retract earlier network requests. Live samples establish only the recorded display successes; unavailable-provider fixtures prove app fallback/lifecycle behavior, never actual source removal or general provider availability. See [extension03 evidence](../.scratch/wheretovisit-discovery/evidence/03/README.md).

## Your branch choice

A social reference can retain one optional canonical ID from the currently published **real Shanghai** catalogue. This is the user's judgment only, labelled **Your branch choice**. It is separate from an imported Mention, extracted evidence, creator endorsement, verification and discovery ranking. Nothing transfers into a Trip or guest view. The limited catalogue may not contain the branch; no match leaves the reference unresolved. The existing real-publication admission rule still requires at least six branches: a smaller publication is truthfully unavailable rather than bypassing that rule.

Review opens a compact native branch selector with no default choice. Name/address and inspectable dated source limits are presented before explicit confirmation. Cancel leaves the existing choice unchanged. Clear requires its own explicit action. Failed writes keep the local selection for retry; a revision conflict requires refreshing the drafts and reopening review. Reading candidates only accesses the app's published catalogue, never a social provider.

Additive migration `0009_bent_blackheart` adds nullable `branch_id` and non-null `choice_revision` defaulting to zero. Existing rows remain unresolved. Only ID/revision are retained, with no copied provider payload or branch facts. The row's original link, note, creation and absolute expiry stay unchanged. Choice metadata shares deletion, session cascade and bounded cleanup with its reference. Reads project current catalogue facts separately; a removed branch, fixture publication, malformed or unavailable catalogue returns a retained unavailable choice without silently clearing or rematching it. Clearing remains possible during catalogue failure.

`PATCH /api/social-references/:id` accepts exactly `branchId` (bounded canonical ID or null) and nonnegative integer `expectedRevision`, with same-origin JSON, 1024-byte maximum, the existing five-second body deadline and no-store/error isolation. Live browser ownership is checked before input/identity decisions. Writes recheck authoritative publication membership and revision in the same transaction and share the existing global/session/IP successful-attempt bounds. Fixtures, unknown and non-Shanghai IDs cannot confer identity even in development. No account claim, lifetime refresh or Trip provenance is created. See [extension05 evidence](../.scratch/wheretovisit-discovery/evidence/05/README.md) for the bounded production acceptance and remaining limits.
