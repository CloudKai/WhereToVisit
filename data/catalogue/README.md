Ticket20 adds manually reviewed practical-fact maintenance through the same private atomic loader. An optional `Place.visitFactChecks` declares all three fields (`address`, `hours`, `operation`), each with `outcome` (`checked`, `unknown`, `failed`, `conflict`), `checkedAt` (ISO date or null), associated `evidenceIds` and a bounded original `explanation`. A checked field requires dated current evidence establishing that field (address uses branch identity); checked hours must cite their exact hours evidence. Checked operation may explicitly record closure. Unknown/failed/conflicting checks expose no current value and never infer closure. The loader trusts the curator's reviewed source rights, as before; this shape confers no source/provider permission.

Legacy batches retain their accepted source-observation dates: address uses current identity evidence, hours their current hours evidence, and operation current operation evidence; missing practical facts have no invented check date. Publishing/reading does not fetch a venue or turn those observations into live checks. Only manually reviewed permitted factual notes and citations are retained; the existing source limitations still apply. No ticket09 research-only candidate or provider payload is admitted by this extension.

Publication refreshes matching-kind saved Trip field metadata in the same transaction, retaining the immutable original Place/recommendation/imported attribution. It stores the latest field result and one last checked fact, with metadata and monotonic material-content versions, for the private Trip lifetime; it adds no full-source cache or unbounded edit history. Invalid publication changes nothing. An explicitly unavailable batch or absent canonical identity yields unknown current facts while keeping historical checked evidence. Changed selected fields flag generated plans for explicit review/regeneration, preserving desired arrangements, membership and votes. A materially changed or conflicting address remains proposed only, blocks current planning and hides practical copy/search actions until same-branch identity is qualified; it never redirects a saved branch. Media eligibility continues independently. Current regular-hour notes do not qualify selected-date exceptions/routes.
